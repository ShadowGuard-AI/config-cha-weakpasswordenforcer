config-cha-weakpasswordenforcer

A keeper behind a grille does the judging here: every credential is tried against a short list of known words, a breach count, and a date reading, and the ones that fail are flagged. No credential value is printed on this page; the checks are stated as facts, with their limits.

Three checks, no more

The tool reads pairs of usernames and credentials, either from two files paired by line position alone or from one YAML configuration file whose keys and values must both be strings, and puts every credential through up to three checks: a common check, a compromised check, and a date check. Any account flagged by any surviving check ends the run at exit 1; a run that flags nobody ends at 0.

Paired by line position alone

python3 main.py [-u USERFILE -p PASSWORDFILE | -c CONFIGFILE] [-w WEAKPASSWORDS] [-t THRESHOLD] [--disable-pwned] [--disable-date] [--disable-common]

The two input files pair by line position alone and must hold the same number of lines; a stray blank line in one shifts every later pairing onto the wrong user. Supplying neither the pair nor the configuration is refused with exit 1.

Six entries in the built-in list

The built-in weak list holds exactly six entries. The common check is exact lowercased membership, so a listed entry with further characters appended escapes it. A named weak-list file that is not found falls back to the built-in six silently, without ending the run.

A count that reaches the threshold is flagged

The compromised check flags at a pwned count greater than or equal to the threshold, default 10, although the help text says more than. A failed lookup warns about that account and does not flag it, so an offline run may pass accounts it never truly checked. If the pwnedpasswords library is not installed and the check has not been disabled, the run refuses at the outset with exit 1. The date check asks whether the whole credential, taken entire, parses as a date.
