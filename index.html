Three Checks, No More

config-cha-weakpasswordenforcer reads pairs of usernames and credentials, either from two files paired line by line or from one YAML configuration file whose entries are username and credential pairs, and it puts every credential through up to three checks, a common check against a list of weak entries, a compromised check against the pwnedpasswords service through its library, which flags a credential whose count in that service has reached the threshold the caller sets, and a date check, which asks whether the whole credential, taken entire and with nothing added, parses as a date, and a run in which any account is flagged by any surviving check ends with exit 1, while a run that flags nobody ends quietly at 0.

Six Entries in the Built In List

-p, --passwordfileNames the companion file of credentials, one to a line. Neither works without the other.
-c, --configfileNames the YAML file that replaces both.
-w, --weakpasswordsNames a file of weak entries to be used instead of the built in list, which holds six entries only, counted and not quoted.
-t, --thresholdSets the count at which the compromised check flags, defaulting to 10.
--disable-pwned, --disable-date, --disable-commonEach retires one check entirely, leaving the others standing.

A Count That Reaches Ten Is Flagged

Flagging occurs when the count reaches the threshold and not only when it passes beyond it. The help text inside the code describes the threshold as flagging a credential pwned more than the stated number of times, while the code flags at greater than or equal to that number, a disagreement the README itself states correctly and the code own help line does not.

A Missing Weak List Falls Back to the Built In Six

A file named there but not found does not end the run, for the program notes the failure and falls back to that built in list.

A Failed Lookup Flags Nobody

The Compromised Check Cannot Run Without Its Library

When the pwnedpasswords library is not installed and the compromised check has not been disabled, the run refuses at the outset with exit 1 and a message telling the caller either to install it or to disable the check.

When a single lookup against the service fails, that account is warned about and not flagged, which means an offline run may pass accounts it never truly checked, and this page says so in those words. When the common check is the only check left standing, its judgement reaches no further than its list, so that a listed weak entry with further characters appended escapes it entirely, a limit the README itself verifies and this page repeats without decoration.

# config-cha-WeakPasswordEnforcer

Checks user accounts for weak or default passwords against a built-in dictionary and common patterns. Employs the `pwnedpasswords` library for checking against compromised password lists and `python-dateutil` for detecting date-based passwords. Reports accounts with potentially vulnerable credentials.

## Install

`git clone https://github.com/ShadowGuard-AI/config-cha-weakpasswordenforcer`

## Usage

`python3 main.py [-u USERFILE -p PASSWORDFILE | -c CONFIGFILE] [-w WEAKPASSWORDS] [-t THRESHOLD] [--disable-pwned] [--disable-date] [--disable-common]`

## Parameters

- `-h`: Show help message and exit

- `-u`, `--userfile`: Path to a file containing a list of usernames (one per line). Use together with `-p`; the two files are paired by line position.

- `-p`, `--passwordfile`: Path to a file containing a list of passwords (one per line).

- `-c`, `--configfile`: Path to a YAML configuration file with user and password information. Use this instead of `-u` and `-p`.

- `-w`, `--weakpasswords`: Path to a file containing a list of weak passwords. Defaults to a built-in list.

- `-t`, `--threshold`: Threshold for the pwnedpasswords check. A password is flagged when its pwned count reaches this threshold (the code uses greater than or equal to, not strictly greater than). Default: 10.

- `--disable-pwned`: Disable checking against the pwnedpasswords database.

- `--disable-date`: Disable date-based password detection.

- `--disable-common`: Disable checking against common password list.

## Verified behavior

- With `--disable-pwned --disable-date`, a user whose credential is one listed weak entry is flagged as a common weak password and the run exits 1.

- Without `--disable-pwned`, when the `pwnedpasswords` library is not installed, the run exits 1 with the message to install it or pass `--disable-pwned`. No live Have I Been Pwned lookup was attempted in this wave.

- The built-in weak list contains only six entries, counted here and not quoted. The common check alone does not flag credentials outside that list, for example a listed entry with further characters appended.
